# 12 怎样写缺陷单

把问题写清楚，别人才能修。不必使用专业术语。下面这一页可以直接复制到记事本或 Word。

建议：**一个问题一张单**。不要把「导入行数不对」和「图的标题不跟着改」写在同一张里。

## 模板（请复制）

```text
标题：（一句话，说出哪里不对）

严重程度：□ 无法继续  □ 结果错误  □ 体验不好

步骤：
1.
2.
3.

期望：（手册或常识认为应该怎样）
实际：（你看见了什么）
是否每次都能复现：□ 是  □ 否（说明哪次不同）

附件：
- 窗口截图（表格 / 图）
- 日志最后几行（可从底部日志面板复制，或 主页 → 设置 → 打开日志文件夹）
```

## 标题怎么起

好标题让人 3 秒知道问题：

| 不好 | 更好 |
|------|------|
| 有 bug | 删除缺失值后 Bob 空 age 的行还在 |
| 排序不行 | 按 score 降序后第一行不是最高分 |
| 保存有问题 | 保存后再打开，绘图页是空的，表还在 |

可以写人名、按钮名、数字。不要写「感觉有点奇怪」当标题。

## 严重程度

- **无法继续**：窗口没了、无法导入、无法保存任何东西。若出现，立刻停止并把日志发给开发者。
- **结果错误**：按钮说成功了，表格/图/文件和手册不一致。优先记这一类。
- **体验不好**：能用，但难懂、易误点。可以记，优先级低于结果错误。

## 步骤要让没看见屏幕的人能照做

写按钮的路径，不要写「按那个蓝色的」。

例如：

1. 数据 → 添加数据，打开 `文档\DataWorkbench\wiki-demo.csv`。
2. 点中间「表格」，顶部出现「操作」。
3. 操作 → 删除缺失值，保持默认，点应用。

然后写期望和实际。期望可以直接抄手册原句。

## 实际结果要写看见的内容

不要只写「不对」。写：

- 表格里仍能看到 `Bob`、`Shanghai`
- 日志写「已导入（10 × 4）」，右侧属性行数是 11
- 记事本打开导出的 csv，第一行是 `Alice,28,...` 而不是列名

## 提交前核对

- [ ] 别人按同样步骤、用同一张示例表，能看到同样现象
- [ ] 有期望、有实际，不是只有感受
- [ ] 有截图或日志
- [ ] 没有把多个无关问题揉成一张单
