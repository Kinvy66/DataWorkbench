# 目标、约束与验收红线

DataWorkbench 要做成一款**工作流驱动的桌面数据分析台**：把重复清洗固定成有向图，用 GUI 操作 pandas，用可导出的图表出论文插图。计算与模型在 Python，界面在 Electron/Vue。

## 主要约束

**特性**

- ✅ **无应用层 C++**：不写 Qt/pybind11/Qwt。CPython、Chromium、Arrow 等原生依赖可作为第三方使用，但不作为本仓库的业务代码。
- ✅ **Python 一等公民**：工作流节点、pandas 清洗、导入导出都在 sidecar 进程执行。
- ✅ **不做 AI Agent**：无 LLM 对话、无工具调用协议、无提示词库、无权限门。工程文件不包含 `agent_sessions/`。
- ✅ **ML Ribbon 做壳**：顶部命令区使用 `@mlightcad/ribbon`（Vue 3 + Element Plus），对齐上游 SARibbon 的产品角色，而不是复刻其实现。
- ✅ **模型-视图分离**：DAG / 参数 / DataFrame 在 Python；节点坐标、停靠布局、图表几何在前端。加载时必须先恢复 Python 模型，再 wrap 视图。

## 产品目标（做什么）

面向科研实验数据与工程一维曲线：同一套清洗对 n 组文件，画一次流程换数据重跑；不熟悉 pandas API 的人也能用对话框和节点完成常用清洗；图表能导出 SVG/PNG/PDF，并允许用属性面板改样式。

## 非目标（明确不做）

| 非目标 | 原因 |
|--------|------|
| 对齐上游「亿级曲线流畅、亿行表格」 | 那是 Qt + Qwt + 虚拟表同进程的设计目标；Web 进程堆和 IPC 成本不同 |
| 1:1 复刻 Qwt 画布拖文本/箭头/探针/3D | 工作量等于再做一个图表产品；放入二期以后 |
| 加载上游 C++ `.dll` 插件 | 进程模型不兼容 |
| 兼容运行上游整个 `.dapro` 的 C++ 布局 XML | 可尝试导入 Python 逻辑段；`workflow.xml` 布局不保证 |
| 内嵌 Jupyter 完整体验 | 可保留「脚本工作区跑一段 py」作为后期，不是 MVP |
| Windows Office COM 深度集成 | 可用 Python `pywin32` 后期做，不进一期 |

## MVP 验收红线

同时满足下列条款才算一期完成，缺一条不算交货：

1. 能导入 csv / xlsx / parquet，在虚表中滚动浏览（数据本体不整表进入渲染进程）。 **已满足**
2. 能从节点面板拖出至少：Start、数据源、一条筛选/query、输出到数据管理器、End；连线后执行，结果出现在数据列表。 **已满足**
3. 能对当前表创建折线图，改标题/轴标签/线色，导出 PNG 与 SVG。 **已满足**
4. 能保存/打开工程 ZIP，关闭重开后节点拓扑、参数、数据集引用仍在。 **已满足**
5. Python sidecar 崩溃后主进程能提示并拉起，不把整个 Electron 打死。 **已满足**
6. 仓库内有针对 RPC 与工作流序列化的自动测试（不要求 UI E2E 全覆盖）。 **已满足**

## 规模红线（性能合同）

把「常用规模」写进合同，避免后期用亿级打回：

| 场景 | 一期必须达标 | 一期不承诺 |
|------|----------------|------------|
| 表格 | 50 万行 × 30 列，滚动流畅，块取数 | 全表单元格编辑的亿级 undo 快照 |
| 折线 | 单系列 20 万点直接画；到 100 万点降采样后仍可缩放 | 多系列合计亿点无降采样 |
| 工作流 | 50 个节点 DAG 执行与保存 | 与上游所有自定义 `paint()` 像素一致 |

## 决策记录摘要

更细的库选型见 [02-tech-stack.md](./02-tech-stack.md)。此处只锁方向：

- 数据**永不**以整表 JSON 穿过 IPC。
- 工作流引擎**复用**上游 `DAWorkFlowPy`，不在 TypeScript 里重写拓扑执行。
- 图表一期是「数据映射 + 属性面板 + 导出」，不是「画布上拖一切」。
- Ribbon 只展示命令；业务走自己的 **command bus**，避免插件绑死 ML Ribbon 内部 API。
